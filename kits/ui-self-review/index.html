UI self-review

Checks your screens for 10 common problems before a designer or user sees them. Give it a screenshot or your front-end code. You get a short, prioritised fix list with where and why.

Download Claude skill (.zip) Download prompt (.md)

What it checks

#AreaLooks for
1StatesEmpty, loading and error states exist and help the user.
2CopyClear labels, no jargon, error messages that say how to fix it.
3Contrast and text sizeText meets WCAG AA contrast and is readable.
4LabelsIcon buttons and fields have accessible names; meaningful images have alt text.
5Keyboard and focusEverything works with a keyboard, with a visible focus outline.
6ConsistencySpacing, buttons, colours and wording follow one system.
7MobileWorks on small screens, with big enough tap targets.
8Destructive actionsDelete and send ask for confirmation or offer undo.
9FormsValidation at the right time, helpful hints, input never lost.
10AI screensSources shown, uncertainty stated, output editable.

How to use it

In Claude (as a skill)

  1. Download ui-self-review-skill.zip.
  2. In Claude, open Settings → Capabilities → Skills and upload the ZIP. (Skills need to be available on your Claude plan.)
  3. Share a screenshot or paste your UI code and ask: "Review this screen."

In Claude Code

  1. Unzip it into ~/.claude/skills/ (or your project's .claude/skills/), then ask Claude Code to review a page or component.

In any other AI assistant

  1. Open ui-self-review-prompt.md, paste it into an assistant that can read images or code, and attach your screen.

Tips

  • Run it on every screen before design review. It catches the boring problems so the review can focus on the hard ones.
  • It doesn't replace a designer or real accessibility testing with users and assistive technology.
  • Add your own design system rules to the checks. It's a plain text file.
