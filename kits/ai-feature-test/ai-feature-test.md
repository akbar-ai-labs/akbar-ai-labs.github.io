# The AI feature test

Answer all seven before you build. If you can't answer one, that's your next piece of work.

| # | Question | What a good answer looks like |
|---|---|---|
| 1 | What decision does this help someone make? | "A credit analyst decides whether to raise a limit, in under 5 minutes." |
| 2 | Does this need AI at all? | Exact counts, totals and rules are handled by queries or code. AI is used only where language or judgement is needed. |
| 3 | What happens when it's wrong? | We know who notices, how they correct it, and what one mistake costs. |
| 4 | Can the user check the answer? | The screen shows the data used and the rule applied. |
| 5 | Where does the data live, and who owns it? | Systems, owners and access are listed, and access is approved. |
| 6 | What does it cost at full scale? | Cost per use × users × uses per day, per month, is written down and acceptable. |
| 7 | How will we know it works? | A set of real examples with the right answers exists before building, and we test against it. |

## How to use it

1. Run it in a 30-minute session with product, design and engineering.
2. Write the answers in the PRD.
3. Any question without a clear answer becomes a task before the build starts.
